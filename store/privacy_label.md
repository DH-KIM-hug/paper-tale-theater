# App Privacy (개인정보 라벨) 답안

작성일 2026-11-06. 기준: 연결 서버 켜는 1.0(결정 2026-11-06), 이름 바꾸기 기능 포함. 근거 코드는 `server/src/*.js`, `entitlements.js`, `package.json`(의존성 Capacitor 뿐), `privacy.html`.

## 결론 (한 줄)
**"데이터를 수집함" + 추적 안 함.** 수집 항목 3개(식별자-사용자 ID, 사용 데이터-제품 상호작용, 구매-구매 내역), 모두 **사용자와 연결됨**, 목적은 **앱 기능** 하나뿐, **추적에 쓰지 않음**. 이름 기능의 '이름'은 아래 §3 판단(추천: 조건부 '수집 아님', 확인 못 하면 보수적으로 신고).

## 1. 먼저: 앱이 서버로 보내는 것 (코드 근거)

## 2. 질문별 답
### Q1. 이 앱이나 제3자 파트너가 이 앱에서 데이터를 수집하나요?
**예.** (서버에 무작위 ID와 진행 기록을 저장하므로. 앱을 기기에만 두고 서버를 끈 판이었다면 '수집 안 함'이었을 것.)

### Q3. 추적(Tracking)에 쓰나요?
**아니오.** 광고·데이터 중개·다른 회사 앱·사이트 데이터와 합치기 없음. ATT(앱 추적 투명성) 요청 불필요, `NSUserTrackingUsageDescription` 도 없음. 제3자 SDK 자체가 없어서 '제3자 파트너가 수집'하는 것도 없음(Cloudflare·ElevenLabs 처리자는 §3·§4).

### Q4. 사용자 삭제 경로
privacy.html '보관과 삭제': 앱을 지워도 서버 기록이 남을 수 있어, hello@ddoystory.com 으로 '기기 번호'와 함께 요청하면 운영자가 그 ID의 모든 기록을 지움(코드: `app.js:140~154` 계정 삭제, 커밋 8f85314d 운영자 삭제 도구). 앱 안 삭제 단추는 없음(판단 필요 항목에 올림).

## 3. 이름 기능의 이름: 수집인가?
**Apple 정의.** "수집(Collect)은 데이터를 기기 밖으로 보내, 당신 또는 제3자 파트너가 **실시간 서비스에 필요한 시간보다 오래** 접근할 수 있게 하는 것." 기기 안에서만 처리하면 수집 아님. 즉 '실시간으로 처리하고 보관하지 않는' 것은 수집이 아니라는 읽기가 가능합니다.

**이 앱의 사실**
- 이름은 요청 한 번 안에서 서버 → ElevenLabs TTS → 소리 파일로 돌아오고, 소리 파일은 기기에만 저장됩니다. 서버는 이름을 KV에 저장하지 않고 로그에 쓰지 않습니다(`docs/NAME_CHANGE_PLAN.md` §4-4~4-5·확정, `name.js`는 `console.error` 에 이름 금지).
- 요청에는 계정·기기 식별자를 넣지 않습니다.
- **구멍:** ElevenLabs가 요청 글을 자기 기록에 남길 수 있습니다. 코드는 `enable_logging=false`(zero retention)를 먼저 시도하고, 요금제가 받지 않으면 **옵션을 빼고 다시 보냅니다**(`name.js:136, 150, 169`). 현재 요금제(Creator)가 zero-retention 을 지원하는지는 문서에 '확인 필요'로 남아 있습니다(NAME_CHANGE_PLAN §6). zero-retention 은 보통 Enterprise 전용이라, 이 확인 전에는 '제3자가 실시간보다 오래 접근할 수 없다'고 단정하지 못합니다.
- 보호자가 직접 입력하는 선택 기능이고, 어린이에게서 받는 것이 아닙니다(부모 확인 뒤 입력).

**판단**
| 경우 | 라벨 | 비고 |
|---|---|---|
| ElevenLabs 쪽 zero-retention 이 실제로 적용됨을 확인(요금제·계약 문서 보관) | 이름은 **수집 아님**(신고 안 함). 위 3개 항목만 | 가장 깔끔. 근거 문서를 남길 것 |
| 확인 못 하거나 폴백(옵션 빼기)이 일어날 수 있음 | **보수적 답: 연락처 정보 > 이름 추가**, 사용자와 **연결 안 됨**, 추적 안 함, 목적 앱 기능 | 신고해도 손해가 거의 없습니다. 미신고가 나중에 발견되면 심사 거절·정정 사유 |
| (참고) 위 보수적 답에 더해 | 'ElevenLabs(제3자 처리자)에 보냄'을 처리방침에 쓰기 | NAME_CHANGE_PLAN §7 의 처리방침 새 절 문구를 privacy.html 에 아직 안 넣었음 → **제출 전 반영 필요** |

**추천:** 1.0 제출 때는 **보수적 답(이름 신고, 연결 안 됨)**. zero-retention 을 문서로 확인하면 다음 업데이트에서 신고를 빼기. (라벨은 앱 업데이트 없이도 언제든 고칠 수 있음.)

## 4. 기타 확인
- **어린이(Kids) 카테고리 규칙(심사 지침 1.3, 5.1.4):** 제3자 광고·분석 금지, 개인 식별 정보·기기 정보를 제3자에게 보내지 않기. 이 앱은 광고·분석 SDK가 없고, 이름 기능은 '이름만 단독'으로 가는 점이 유일한 쟁점입니다(심사관이 문제 삼을 수 있음). 심사 노트에 이름 기능이 보호자 전용·부모 확인 뒤·선택임을 적었습니다(`review_notes.md`).
- **Cloudflare:** 서버 호스팅 사업자로서 접속 IP를 인프라 수준에서 처리합니다. 앱 코드는 IP를 읽거나 저장하지 않습니다. 일반적으로 처리자 인프라의 일시적 접속 처리는 신고 대상으로 보지 않지만, 가장 엄격하게 하려면 '식별자'에 관한 설명을 처리방침에 한 줄 더 넣을 수 있습니다(판단 필요 아님, 참고).
- **PrivacyInfo.xcprivacy(앱 매니페스트):** 아직 없음(APP_LAUNCH_CHECKLIST §3 '확인 필요'). 위 라벨과 같은 내용(`NSPrivacyCollectedDataTypes`: UserID, ProductInteraction, PurchaseHistory, 목적 AppFunctionality, 연결됨, 추적 아님, `NSPrivacyTracking=false`)을 Archive 의 Privacy Report 로 확인한 뒤 추가하세요. 앱 코드는 이번 작업에서 고치지 않았습니다.
- **웹 공개판:** 서버를 쓰지 않음(privacy.html). 앱 라벨과 무관.

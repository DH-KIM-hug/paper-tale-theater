# (지난 안) 스티커북 퍼즐 기획 — 갈래별로 이어지는 직소 조각 긴 그림 (동화 한 편 = 조각 하나, 모양 하나 고정)

2026-10-27 사용자 최종 결정: "드래곤볼 만화책 측면 표지(책등)가 쭉 이어지는 것처럼. 퍼즐 스티커는 사실 흰 테두리가 없어. 새 동화가 나오면 그 동화 컨셉으로. 우리 뒷표지 만든 게 스티커화+퍼즐화 돼서 쭉 오른쪽으로 이어진다고 생각하면 돼. 물론 단순 사각 스티커면 안 되겠지."

- **퍼즐 조각 = 그 동화의 대표 장면 그림 한 장(인물 포함).** 끝 화면 뒷표지(`assets/thumbs/<id>_back_tall|_back_wide`) 컨셉을 바탕으로 한다. 이전 안의 '장소만 그리고 스티커 합성'은 버린다.
- 조각 모양은 **직소 퍼즐 모양**(위·아래 평평, 왼쪽 홈·오른쪽 돌기, 표준 모양 하나). 모양은 생성이 아니라 코드·후처리 마스크로 오린다. **흰 테두리 없음**, 그림이 조각 가장자리까지 꽉 참. 조각 사이에는 아주 얕은 웜 그림자만.
- 갈래 판마다 조각이 왼→오로 이어져 **한 장의 긴 그림**이 된다. 조각 좌우 가장자리의 층 높이·색은 판별 고정값(§3).
- 아직 안 한 동화 = 같은 직소 모양의 실루엣 자리(크림 종이에 눌린 모양). 받으면 색 조각이 채워진다. 새 동화 = 그 컨셉 조각을 오른쪽 끝에 붙임.
- 창작 판(구름 공장·빨간 자동차·유니콘, 아이 캐릭터 포함 — CLAUDE.md §1 예외)을 **시범 판**으로 먼저 생성한다(작업표 `batch: "pilot"`).
- 별개 기능 구분: **동화별 캐릭터 스티커 세트(10장)** 는 이 퍼즐과 다른 것으로, 흰 칼선 스티커를 유지하고 그림마다 크기가 달라도 된다(구름 공장 넷은 크게). 이 문서는 퍼즐 조각만 다룬다.

관련: docs/APP_SCREENS_PLAN.md S3·S7, docs/MONETIZATION.md §1, docs/SYNC_API.md `stickers`, home.js `BOARDS`·`drawStickers`, engine/reward3d.js, 작업표 tools/app/gen/jobs_puzzle.json. 코드 구현은 다른 담당.

## 2. 조각 규격 (직소 모양·마스크·좌표)

### 2-1. 치수 (px, 저장 기준)
| 항목 | 값 | 설명 |
|---|---|---|
| 몸통 | **768 × 1024** (3:4, 세로) | 책등처럼 세로로 긴 조각이 나란히 선다. 위·아래 변은 평평 |
| 돌기(오른쪽) | 돌출 **124**, 목 폭 80(y 472~552), 머리 지름 120(중심 832,512), 중심 y = 512 | 몸통 오른쪽 변 밖으로 튀어나옴. 머리가 목보다 넓어야 맞물려 보여서 처음 값(목 120·머리 200)에서 바꿈 |
| 홈(왼쪽) | 돌기와 같은 모양을 몸통 왼쪽 변 안쪽으로 판 것 | 앞 조각의 돌기가 들어온다 |
| 조각 그림 파일 | **896 × 1024** (= 몸통 768 + 돌기 영역 128), 투명 png→webp, 직소 마스크 적용 | `assets/ui/piece_<id>.webp` |
| 생성 크기 | **1024 × 1024** (GPT 정사각) | x 0~128 여백(버림) + 몸통 x 128~896 + 돌기 영역 x 896~1024 |
| 긴 그림에서 조각 n 의 왼쪽 몸통 변 | x = (n−1) × 768 | 돌기 128 이 다음 조각의 홈에 겹친다 |
| 긴 그림 폭 | N × 768 + 128 | 공주·세계 6272, 옛이야기·이솝 4736, 창작 2432 |

### 2-2. 표준 직소 경로 (마스크, 몸통 좌표계 0,0 ~ 768,1024)
- 위 변: (0,0)→(768,0) 직선. 아래 변: (768,1024)→(0,1024) 직선.
- 오른쪽 변: (768,0)→(768,472) → 목 (768,472)→(787.28,472) → 머리: 중심 (832,512) 반지름 60 의 큰 원호(오른쪽으로 볼록, x 최대 892) → (787.28,552)→(768,552) → (768,1024). 정확한 경로는 `tools/app/gen/piece_mask.svg`.
- 왼쪽 변: 같은 모양을 x=0 변 **안쪽**(x 0~128)으로 판다(오른쪽 변 경로를 x 축으로 768 만큼 옮긴 것).
- 모서리는 반지름 12 로 둥글린다(가위질). 실제 경로 숫자는 구현 때 `tools/app/gen/piece_mask.svg` 한 파일에 두고 CSS `clip-path: path()`·후처리(PIL)·reward3d 카드가 **같은 파일**을 쓴다.
- 조각 사이 그림자: 각 조각에 `filter: drop-shadow(0 1px 2px rgba(46,36,28,.35))` 정도. 흰 테두리·윤곽선 없음.

### 2-3. 조각 안 구역 (생성 이미지 1024×1024 기준 x)
| 구역 | x 범위 | 내용 |
|---|---|---|
| 버리는 여백 | 0~128 | 이음 띠와 같은 4색 띠만(잘려 나감) |
| 왼쪽 이음 띠(홈 영역) | 128~256 | 4색 띠만(§3). 앞 조각의 돌기가 들어온다 |
| **가운데 무대** | **256~768** (512px) | 인물·주요 사물·그 동화 장소. 인물 발끝 y ≈ 860(84%), 인물 높이 ≈ 460(45%) |
| 오른쪽 이음 띠 | 768~896 | 4색 띠만 |
| 돌기 영역 | 896~1024 | 4색 띠만(돌기 안에 들어가는 그림) |

## 3. 이음 규칙 (판별 고정 — 모든 조각의 좌우 가장자리)
- 가로 층 높이 전 판 공통(y, 1024 기준): **하늘 0~410 · 먼 층 윗선 330~470 사이에서 출렁이되 이음 띠 안에서는 정확히 410 · 지평선 471 · 가운데 땅 471~758 · 땅선 758 · 앞 땅 758~1024.** 앞 가림 잎·풀은 앞 땅 위 25% 이하, 무대 구역 안에서만.
- 판마다 **이음 4색**(하늘·먼 층·가운데 땅·앞 땅) 고정(§10-2 표). 이음 띠(왼쪽 128~256, 오른쪽 768~1024)에는 이 네 색의 평평한 띠만: 사물·소품·잎·해·구름·그림자·빛 없음. 큰 덩어리는 무대 구역 안에서 끝난다.
- 카메라·광원 판 안 고정: 멀리·눈높이·정면, 광원 왼쪽 위. 원근법 없음. 밤 장면은 하늘색을 바꾸지 않고 달·등불 소품으로만(판단 6).
- **이음 띠 자동 평탄화**(후처리, 권장): 생성 결과의 두 이음 띠·돌기 영역을 판의 4색·고정 높이로 **코드가 다시 칠한다**(안쪽으로 24px 페더, 종이결 질감 곱하기). 그러면 어떤 조각끼리도 정확히 이어지고, "앞 조각 오른쪽 끝 띠 살짝 맞춤"이 자동으로 된다. 생성이 띠를 지켰으면 거의 바뀌지 않는다(판단 5).

## 4. 생성·후처리 절차 (판 안 직렬)
1. 배치표에 id 추가 → 순번 n.
2. 작업표 `piece_<id>`(kind piece, 1024×1024). **refs** = ① 그 동화 뒷표지 `assets/thumbs/<id>_back_tall.webp`(장면 컨셉) ② `_back_wide.webp`(보조) ③ 인물 기존 자세 그림(assets/v3w, 생김새) ④ n≥2 이면 **앞 조각 생성 결과 png**(프롬프트가 "그림의 오른쪽 1/8 띠를 이어서" 라고 지시) — 따로 띠 파일을 만들지 않아 `run_simple.py` 로 순서대로 돌리기만 하면 된다.
3. 생성 1024×1024 → `tools/app/gen/post_puzzle.py`(신설): 이음 띠 평탄화(§3) → x 128~1024 자르기(896×1024) → 직소 마스크(`piece_mask.svg`) 적용 → `assets/ui/piece_<id>.webp`(투명). 검사 수치: 이음선 네 띠 경계 y ±12px, 띠 색차.
4. 캡처(아이패드 가로 두 조각 보기)로 이음·인물 크기(이웃 조각과 머리 크기 같게, CLAUDE.md §4-1)를 눈으로 확인. 인물이 너무 크거나 작으면 그 조각만 재생성(앞 조각은 안 바뀜).
5. `assets/ui/ui.js` 등록, `?v=` 올리기.
- 지금 31조각: 판별로 1→2→…(앞 조각이 다음 refs). 시범 = 창작 판 3조각(`batch: "pilot"`), 나머지 28 = `batch: "main"`.

## 6. 완성 개념과 기록
- 판의 조각 수 N = 배치표 길이(공개·만드는 중·잠김 모두). 받은 수 = `stickers ∩ 배치표`.
- 완성 판정: 받은 수 == N 이고 로컬 `puzzleDone[판]` 목록에 N 이 없음 → 축하 + `puzzleDone[판].push(N)`.
- 새 조각이 붙어 N+1 이 되면 '받은 수 N / N+1', 새 자리만 실루엣. 판 머리 종이별은 한 번이라도 완성한 판에 영구. 다시 다 채우면 또 축하(같은 연출·문구).
- 축하 연출(S3 에서 한 번): 팡파르 → 긴 그림이 끝까지 천천히 흘러가며(가로 자동 스크롤 1.6초) 조각들이 차례로 살짝 들렸다 내려앉음(0.9초, 110ms 간격) → 뒤에서 환해짐(`.pz-glow`) → 색종이 2초 → 음성 "공주 퍼즐을 다 모았어요!".
- 옛 `puzzleDone = {princess:true}` 는 버리고, 첫 실행 때 이미 완성인 판은 연출 없이 `[N]` 을 조용히 기록.

## 11. 새 동화 체크리스트 (동화 한 편이 늘 때)
1. `tales/puzzle.js` 해당 판 배열 **끝**에 id 추가(공주 동화는 princess). 커밋 뒤 바꾸지 않는다. `node tools/app/check_app_data.mjs` 통과.
2. 뒷표지(`_back_tall`·`_back_wide`)가 먼저 있어야 한다(조각 컨셉의 바탕).
3. 조각 1장: jobs_puzzle.json 에 `piece_<id>`(판 공통 블록 + 장면 한 줄 + 인물 refs + 앞 조각 png, `pass` = 순번) → `run_simple.py puzzle piece_<id>` → `post_puzzle.py`(이음 평탄화·자르기·마스크) → `assets/ui/piece_<id>.webp` → ui.js.
4. 앞 조각은 손대지 않는다(이음 띠는 둘 다 평탄화돼 있어 자동으로 맞는다). 혹시 앞 조각의 띠 높이가 옛 규칙이면 그 조각만 `post_puzzle.py` 를 다시 돌린다(인물·장면은 그대로).
5. index.html `?v=` 올리기. 캡처 3종(1366×1024, 1024×1366, 390×844): 새 자리가 실루엣으로 끝에 붙었는지, 이음선이 튀지 않는지, 완성했던 판의 종이별이 남아 있는지, 이웃 조각과 인물 머리 크기가 같은지.
6. 조각 그림이 아직 없으면 받은 조각은 썸네일을 직소 마스크로 오려 임시 표시.

## 12. 확정 사항(이 문서 기준, 사용자 확인 전)
- 갈래 5판, 동화 1편 = 직소 조각 1개(몸통 768×1024, 오른쪽 돌기 128·왼쪽 홈, 표준 모양 하나, 흰 테두리 없음, 그림 꽉 참). 조각은 왼→오로 맞물려 판마다 긴 그림 한 장.
- 조각 그림 = 그 동화 대표 장면(인물 포함), 뒷표지 컨셉 기반, 좌우 이음 띠는 판별 4색·고정 높이(후처리 평탄화).
- 아직 안 한 동화 = 같은 모양의 크림 실루엣. 새 동화 = 오른쪽 끝에 조각 추가, 앞 조각 불변.
- 완성 = 지금 있는 조각 전부 채움, 기록은 조각 수별 목록, 종이별 영구, 다시 다 채우면 또 축하.
- 시범 = 창작 판 3조각(`batch: "pilot"`). 캐릭터 스티커 세트(10장, 흰 칼선, 크기 자유)는 별개.
- 데이터는 `stickers[]` 로 충분, 서버 변경 없음.

# 스티커북 퍼즐 기획 — 갈래별 이어지는 긴 그림(파노라마)

2026-10-27. 사용자 결정: "퍼즐은 새로 동화 나오고 기존 거에 붙이려면 끝부분을 살짝 조정하고 새 그림을 붙이는 걸로 해야겠네."
→ 갈래 판마다 **이어지는 긴 그림 한 장**. 동화 한 편 = 그림 한 **마디**. 새 동화가 나오면 기존 그림의 **오른쪽 끝 띠를 살짝 고쳐 그려 이어지게 하고 새 마디를 붙인다**(앞 마디들은 그대로).
같은 날 함께 결정: 스티커는 크림 또는 흰 칼선 테두리를 둔다(CLAUDE.md §7-1 예외). 「구름 공장」·「나의 빨간 자동차」(이현이)·「유니콘을 찾아서」(다현이)의 아이 캐릭터는 그대로 공개하고 스티커·퍼즐에도 쓴다(§1 예외).
이 문서 이전의 '4칸 권' 안은 비교안으로만 §1 에 남긴다.

관련: docs/APP_SCREENS_PLAN.md S3·S7, docs/MONETIZATION.md §1, docs/SYNC_API.md `stickers`, home.js `BOARDS`·`drawStickers`, 작업표 tools/app/gen/jobs_puzzle.json. 코드 구현은 다른 담당.

## 2. 구조 한눈에

- **판**(board) = 갈래 5개 고정: 공주 `princess` · 우리 옛이야기 `korean` · 이솝 동물 친구 `aesop` · 세계 명작 `world` · 창작 동화 `original`.
- **마디**(segment) = 동화 한 편의 그림 영역. 판의 긴 그림은 마디 파일 N장을 왼쪽부터 오른쪽으로 이어 붙인 것. 마디 순번은 배치표(`tales/puzzle.js`, 끝에만 추가) 순서이고 영원히 안 바뀐다.
- 마디의 두 상태: **실루엣**(동화는 있는데 아이가 아직 놀이로 끝까지 안 함: 마디 그림이 새김 상태 + 스티커 실루엣) / **스티커**(받음: 마디 그림이 켜지고 컬러 스티커가 무대에 섬). '안 뚫린 칸' 같은 미래 자리는 없다 — 긴 그림은 지금 있는 마디에서 끝나고, 끝 마디의 오른쪽 띠가 '열린 끝'이라 언제든 이어 붙일 수 있다.
- **완성** = 지금 있는 마디를 모두 받음 → 축하. 새 마디가 붙으면 그 마디만 실루엣으로 새로 보이고, 다시 다 모으면 또 축하. 이전 완성의 종이별 표시는 지우지 않는다(§6).
- 인물은 마디 그림에 그리지 않고 **스티커가 마디의 무대 좌표에 서는 합성**(§4, 권장안).

## 3. 마디 규격과 이음 규칙

### 3-1. 치수 (저장 기준)
| 항목 | 값 | 이유 |
|---|---|---|
| 마디 저장 크기 | **1280×1024** (5:4) | 한 화면에 두 마디(아이패드), 세로 화면에서도 마디 하나가 크게 보임 |
| 생성 크기 | **1536×1024** (3:2, GPT 기본 크기) = 이음 띠 256 + 마디 1280 | 왼쪽 256 = 앞 마디 끝 띠 다시 그린 것, 오른쪽 1280 = 새 마디 |
| 이음 띠 J | **256px** (마디 폭의 20%) | 앞 마디의 x 1024~1280 영역. 이 띠만 다시 그려 바꾼다 |
| 열린 끝 띠 | 모든 마디의 오른쪽 256px(= 생성 이미지의 오른쪽 256px) | 이어 붙일 수 있게 '이음 층'만 있는 띠 |
| 긴 그림 높이 | 1024 고정 | 마디 수와 무관 |

### 3-2. 가로 띠(층) 높이 고정 — 모든 판 공통 (y 는 1024 기준)
| 층 | y 범위 | 규칙 |
|---|---|---|
| 하늘 | 0 ~ 410 | 판의 **하늘색 한 장**. 해·달·구름은 마디 안쪽(x 256~1024)에만 |
| 먼 층(능선·숲선·구름 띠) | 윗선 330~470 사이에서 출렁임, **이음 띠 안에서는 윗선 y=410 정확히** | 판의 **먼 층 색 한 장** |
| 지평선(먼 층 ↔ 가운데 땅) | 470 | 마디 안에서도 바꾸지 않음 |
| 가운데 땅(무대가 놓이는 땅) | 470 ~ 760 | 판의 **가운데 땅색**. 집·나무·연못 같은 장소는 이 층에 |
| 앞 땅 | 760 ~ 1024 | 판의 **앞 땅색**. 땅선 y=760 고정 |
| 앞 가림 잎·풀 | 앞 땅 위, 높이 1024 의 25% 이하 | 마디 안쪽(x 256~1024)에만. 이음 띠에는 없음 |

- **이음 4색**: 판마다 하늘·먼 층·가운데 땅·앞 땅 색 넷을 고정한다(§11-2 표). 이음 띠(마디의 왼쪽 0~256, 오른쪽 1024~1280)에는 이 네 색의 평평한 띠 **만** 있다: 사물·소품·잎·그림자 띠·빛 없음. 그래서 어떤 마디 끝에 어떤 마디가 와도 이어진다.
- 마디 안쪽(x 256~1024, 폭 768)에 그 동화의 장소·소품·무대를 둔다. 큰 덩어리(언덕·성벽)는 안쪽에서 시작해 이음 띠 **앞에서** 끝난다(걸치지 않음).
- 카메라·광원은 판 안에서 고정: 멀리·눈높이·정면, 광원 왼쪽 위(그림자 오른쪽 아래). 원근법 없음.
- 밤 판(없음, 지금 다섯 판 모두 낮)은 만들지 않는다. 밤 장면이 필요한 동화(까치·백설공주)는 마디 안쪽 소품(달·등불)으로만 표현하고 하늘색은 판 색 그대로.

### 3-3. 열린 끝 규칙
- 모든 마디의 오른쪽 256px 는 §3-2 의 이음 4색 띠만 있는 '열린 끝'으로 그린다. 그림이 '끝났다'는 표시(액자·절단·말림)를 넣지 않는다. 화면에서는 긴 그림이 거기서 그냥 끝난다(구멍의 오른쪽 테두리).
- 첫 마디의 왼쪽 256px 도 같은 띠(생성 이미지의 왼쪽 256 은 버리므로 결과 파일의 왼쪽 가장자리가 띠가 된다).

## 4. 새 마디 생성·이어 붙이기 절차 (앞 마디의 끝 띠만 다시 그린다)

1. 배치표에 동화 id 를 그 판 배열 끝에 추가 → 순번 n.
2. 작업표 항목 `puzzle_<판>_<n>` 생성(kind bg, 1536×1024). **refs** = ① 앞 마디 `puzzle_<판>_<n-1>` 의 생성 결과 png(전체 — 색·결·층 높이 참고) ② 앞 마디의 끝 띠만 잘라 둔 `puzzle_<판>_<n-1>_end.png`(x 1024~1280, 256×1024 — 왼쪽 띠를 '이것을 이어서' 그리게) ③ 새 동화의 시작 화면 키아트 `assets/thumbs/<id>_key_wide.webp`(장소 어휘).
   - 프롬프트: "왼쪽 256px 는 참고 ②의 띠를 **그대로 이어서** 다시 그린다(같은 네 색, 같은 높이, 사물 없음). 그다음 768px 에 이 동화의 장소. 오른쪽 256px 는 열린 끝."
3. 생성 결과를 나눈다: 왼쪽 256 → 앞 마디 파일의 x 1024~1280 에 **덮어쓴다**(경계 x=1024 에서 왼쪽으로 48px 페더로 섞음). 오른쪽 1280 → 새 마디 파일.
   - 첫 마디(n=1)는 ①② 없이 생성하고 왼쪽 256 을 버린다.
4. 앞 마디는 이름 그대로 저장(내용만 끝 띠가 바뀜). 새 마디의 끝 띠도 `_end.png` 로 잘라 둔다(다음 동화용).
5. 검사: 이음선(x=1024/0)에서 네 띠의 경계 y 가 ±12px 안, 색차가 작은지 스크립트로 비교하고, 캡처(아이패드 가로 2마디 보기)로 눈으로 확인.
6. 그래도 이음이 튀면 두 가지 중 하나: (가) 그 생성을 다시 돌린다(끝 띠는 사물이 없어 재생성 비용이 작다) (나) 이음선 위에 판 공통 **앞 가림 잎 한 장**(`puzzle_join_<판>.webp`, 앞 땅에서 올라오는 덤불, 높이 25% 이하)을 코드가 얹어 가린다 — §10 판단 5.
- 지금 31마디는 같은 절차를 판별로 순서대로 돌린다(한 판 안에서는 직렬, 판끼리는 병렬 가능). 작업표의 `pass` = 마디 순번.
- 후처리 스크립트(`tools/app/gen/post_puzzle.py`, 신설 예정): 생성 png → (n≥2) 앞 마디 끝 띠 교체 → 1280×1024 webp → `_end.png` 저장 → 이음 검사 수치 출력.

## 5. 마디 안의 인물: 스티커 합성 유지 (권장)

| | (가) 마디는 장소만, 스티커가 무대에 선다 (권장) | (나) 마디 그림에 인물까지 그린다 |
|---|---|---|
| 완성 전 모습 | 새김 상태 장소 + 스티커 실루엣 | 새김 상태 장면(인물 포함) + 스티커 실루엣 → 인물이 둘로 보임 |
| 받은 뒤 | 장소가 켜지고 **아이가 모은 바로 그 스티커**가 선다 | 장면 속 인물 + 그 위 스티커(겹침), 또는 스티커를 안 올리면 '붙였다'는 느낌이 사라짐 |
| 인물 그림 바뀔 때 | 스티커만 다시 | 마디 재생성 + 이음 다시 |
| 종이 어휘 | 키아트와 같은 '판 + 스프라이트 합성' | 생성 인물이 게임 스프라이트와 달라질 위험 |

→ **(가)**. 마디마다 **무대**(평평한 빈 자리)를 가운데 땅에 둔다.
- 무대 좌표(1280×1024 기준): 스티커 **발끝 (640, 880)**, 스티커 표시 높이 **380px**(마디 높이 37%) → 스티커가 x 450~830, y 500~880 을 차지. 이음 띠(x<256, x>1024)와 190px 이상 떨어진다. 무대 자리(x 400~880, y 520~900)는 비운다. 소품은 무대 좌우에.
- 좌표는 `assets/ui/puzzle_anchors.json` 에 마디별로 적는다(기본값 위, 그림을 받은 뒤 무대가 다르면 덮어씀).
- 두 아이 스티커(오누이·헨젤과 그레텔·구름 공장)는 폭이 넓으므로 높이 340px 로 줄여 x 380~900 안에 들게 한다(발끝 같음).

## 6. 완성 개념과 기록

- 판의 마디 수 = 배치표 길이 N(동화 전부: 공개·만드는 중·잠김 포함). 받은 수 = `stickers ∩ 배치표`.
- **완성 판정**: 받은 수 == N 이고, 로컬 `puzzleDone[판]` 목록에 N 이 없음 → 축하 연출 + `puzzleDone[판].push(N)`.
- 새 마디가 붙어 N 이 N+1 이 되면: 판은 '받은 수 N / N+1' 로 보이고 새 마디만 실루엣. **이전 완성 표시(종이별)는 그대로 남는다**(판 머리의 종이별은 한 번이라도 완성한 판에 영구 표시). 다시 다 모으면 또 축하하고 `puzzleDone[판]` 에 N+1 추가.
- 축하 연출(S3 에 들어왔을 때 한 번): 팡파르 → 긴 그림이 끝 마디까지 천천히 흘러가며(가로 자동 스크롤 1.6초) 마디 사이 새김이 모두 걷히고 뒤에서 환해짐(`.pz-glow`) → 마지막에 받은 스티커가 무대로 미끄러짐 → 색종이 2초 → 음성 "공주 퍼즐을 다 모았어요!". 두 번째 이후 완성은 같은 연출, 문구 같음.
- 기존 기록 이전: 지금 `puzzleDone = {princess:true}` → `{princess:[N_당시]}` 를 알 수 없으므로 옛 키는 버리고, 첫 실행 때 이미 완성인 판은 연출 없이 `[N]` 을 조용히 기록(§10 판단 7).

### 7-1. 아이패드 가로 (1366×1024, 왼쪽 레일 128)
```
┌────┬───────────────────────────────────────────────────────────────────┐
│로고│                                                         [⚙]       │
│    │ ((공주 ★ 6/8)) ((옛이야기 3/6)) ((이솝 4/6)) ((세계 2/8)) ((창작 3/3)) │
│(동화)│                                                                  │
│    │  ‹ ┌───────────────┬───────────────┐ ›        ┌──────────────┐   │
│(잠자리)│ │  마디 3        │  마디 4        │          │ (( 별 접시 )) │   │
│    │    │ [스티커 무대]   │ [실루엣 무대]   │          │  ★ ★ ★ · ·   │   │
│((스티커북))│ 인어공주       │ 미녀와 야수     │          │    3 / 5     │   │
│    │    └───────────────┴───────────────┘          └──────────────┘   │
│    │      ○ ○ ● ● ○ ○ ○ ○    공주 퍼즐  6 / 8                          │
└────┴───────────────────────────────────────────────────────────────────┘
```
- 구멍 하나(가로 820 × 세로 328)에 긴 그림이 들어가고 **두 마디**가 보인다(마디 410×328). 가로 스와이프 또는 ‹ › 로 한 마디씩 스냅. 아래 점 = 마디 수와 지금 보이는 두 마디(채운 점). 처음 열 때 위치 = **첫 실루엣 마디**가 왼쪽에 오게(모두 받았으면 마지막 두 마디).
- 판 머리 구멍: 한 번이라도 완성한 판은 작은 종이별 ★ 영구 표시 + 숫자 '받은 수 / 마디 수'.
- 톡: 스티커 = 제목 읽기 + 들썩. 실루엣 = "아직 비어 있어요". 긴 그림 빈 땅 = 아무것도 안 함. 판 구멍 = 판 바꾸기 + 이름 읽기.
- 긴 그림의 왼쪽·오른쪽 끝은 구멍 테두리에서 그냥 끝난다(첫 마디 왼쪽 띠, 끝 마디 열린 끝 띠).

### 7-2. 아이패드 세로 (1024×1366, 아래 막대)

### 11-4. 작업표 실행 순서
1. 스티커 31(병렬 가능). 2. 마디: 판별로 1→2→…(앞 마디 결과가 다음 refs). 한 번에 적게 요청(한도). 3. 마디마다 `post_puzzle.py` 로 끝 띠 교체·webp·이음 검사. 4. ui.js 등록, `puzzle_anchors.json`, `?v=`, 캡처 3종 확인.

## 12. 새 동화 체크리스트 (동화 한 편이 늘 때)
1. `tales/puzzle.js` 해당 판 배열 **끝**에 id 추가(공주 동화는 princess). 커밋 뒤 바꾸지 않는다. `node tools/app/check_app_data.mjs` 통과.
2. 스티커 1장: jobs_puzzle.json 에 `sticker_<id>`(refs = 대표 자세 그림, 흰 칼선) → 생성 → chromakey → 512² → `assets/ui/sticker_<id>.webp` → ui.js.
3. 마디 1장: `puzzle_<판>_<n>` 항목(refs = 앞 마디 png + 앞 마디 `_end.png` + 새 키아트, 판 공통 블록 §11-2, 장소 한 줄) → 생성 1536×1024 → `post_puzzle.py`: 왼쪽 256 을 앞 마디 끝 띠에 덮어쓰기(48px 페더) + 새 마디 1280×1024 webp + `_end.png` → 이음 검사.
4. `assets/ui/ui.js` 에 `puzzle_<판>_<n>` 추가, 무대가 기본 좌표와 다르면 `puzzle_anchors.json`.
5. index.html `?v=` 올리기. 캡처 3종(1366×1024, 1024×1366, 390×844): 새 마디가 실루엣으로 끝에 붙었는지, 앞 마디 이음선이 튀지 않는지, 완성했던 판의 종이별이 남아 있는지.
6. 마디 그림이 아직 없으면 그 마디는 판 공통 4색 띠(CSS)만으로 임시 표시(스티커는 정상). 스티커가 없으면 썸네일 둥글게(지금 방식).

## 13. 확정 사항(이 문서 기준, 사용자 확인 전)
- 갈래 5판, 판마다 마디(동화 1편 = 1마디)를 이어 붙인 긴 그림. 마디 1280×1024, 이음 띠 256, 층 높이·이음 4색 판별 고정, 끝 마디는 열린 끝.
- 새 동화 = 스티커 1 + 마디 1(생성 1536×1024, 왼쪽 256 으로 앞 마디 끝 띠만 교체). 앞 마디들은 안 변한다.
- 완성 = 지금 있는 마디 전부 받음. 기록은 마디 수별 목록, 종이별 표시는 영구, 다시 다 모으면 또 축하.
- 인물은 스티커 합성(무대 발끝 (640,880), 높이 380). 스티커는 흰 칼선(권장, 판단 3). 창작 3편은 아이 캐릭터 스티커.
- 데이터는 `stickers[]` 로 충분, 서버 변경 없음.

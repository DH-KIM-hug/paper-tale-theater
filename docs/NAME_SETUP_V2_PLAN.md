### 2-3. 화면 3 — 가족 동화 설정 (`mock_family_*.png`, 구름 공장)

- 아이 셋을 **카드 3장**(아이패드 한 줄, 휴대폰 세로 쌓기)으로: 아바타(실제 스프라이트) + "첫째 / 둘째 / 막내(아기)" + "지금은 다현이" + 세그먼트 [여자아이][남자아이] + 한글 이름 칸.

- 맨 아래 한 줄: 동의 체크 + "영어 이름 적기" 링크(누르면 칸 3+1개가 펼쳐짐. 기본은 접힘) + 1차 행동 '이렇게 완성'.
- 조합: 모습은 아이마다 따로 고르므로 남남남·여여여·남여남… 모두 가능. 나이 순서(첫째·둘째·막내)는 고정이다(대사의 '삼남매'·행동 순서가 나이에 묶여 있고, 이름 자리 A=첫째·B=둘째·C=막내가 그대로).
- 휴대폰에서는 1차 행동이 네 번째 카드 아래로 내려간다(목업 확인). 구현 때는 **아래에 고정(sticky)** 막대로 둔다.

### 2-4. '성별'이 아니라 '주인공 모습'으로 쓰는 이유 (중립 선택지를 두지 않는 이유)

- App Store 심사 지침에 성별 선택지를 셋 이상 두라는 규정은 없다. 여기서 고르는 것은 사용자의 성별이 아니라 **그림 속 주인공의 모습**이다(아바타 고르기와 같다). 그래서 문구를 '남/여'가 아니라 '여자아이 / 남자아이'로 쓰고, 설정 이름도 '주인공 모습'으로 한다.
- 중립을 셋째 선택지로 두면 그림이 한 벌 더 필요(동화 안 104장 → 156장)하고, 3~4세 보호자에게 선택지가 늘어 화면이 다시 복잡해진다. 지금 그림 중 빨간 자동차의 이현이(노란 티셔츠·반바지)와 구름 공장 막내는 이미 중립에 가까워, 실제로는 '남자아이' 판이 중립 역할을 겸한다.
- 심사에서 문제 삼으면(가능성 낮음) 세그먼트에 세 번째 '아무거나' 를 넣고 그림은 남자아이 판을 재사용하는 것으로 대응한다(그림 추가 없음, 판단 §7-2).

### 2-5. 글자 최소화 원칙 (홈 UI 2판 §7-5 적용)

- 바탕 `#F3F3F1`, 카드 흰색, 그림자 `--sh-1`(옅은 중립 회색 + 1px 테두리), 입력 칸은 흰 바탕 + `--cut` 1px 테두리(음각 없음), 1차 행동 감빛 `#D9622F` 화면당 하나, 보조 단추는 흰 알약 + 2px 먹선.

- 세그먼트·칩·체크는 모두 단색 기호, 아이콘 그림 없음.

### 3-4. 새 주인공 그림 규칙

- **실제 아이 사진 참고 금지**(CLAUDE.md §1·§7-7): 반대 모습 판은 일반 캐릭터다. 구름 공장 기존 작업표의 refs 에 `~/.paper-tale/refs/family/*.jpg` 가 들어 있는데, 새 판 작업표에는 **사진 ref 를 넣지 않는다**. ref 는 기존 생성 그림(같은 자세)만.

- 얼굴은 재사용하지 않는다(§7-7 "같은 얼굴을 여러 인물에 재사용하지 않는다"): 유니콘·사탕 마녀의 남자아이판은 **같은 남자아이**(두 편의 다현이가 같은 얼굴이듯)로 하되, 빨간 자동차의 여자아이판·구름 공장 아이들과는 다른 얼굴로 한다.

### 4-3. 템플릿 문법 제안 (engine/name_form.js · server/src/name_form.js 공통)

지금: `{A}` 이름, `{A:이가/가}` 받침 조사, `{A_en}` 영어 이름.

| 새 문법 | 뜻 | 예 |
|---|---|---|
| `{A_g:남/여}` | 자리 A 의 **모습**으로 고른다. 앞이 남자아이, 뒤가 여자아이 | 영어: `{A_g:He/She} rolled and rolled…`, `in {A_g:his/her} basket`, `said to {A_g:himself/herself}` |
| `{A>B:형/오빠/누나/언니}` | **호칭**: A가 B를 부를 때. 네 값 순서 = (A남·B남)/(A여·B남)/(A남·B여)/(A여·B여). 영어는 `{A>B:brother/brother/sister/sister}` 처럼 두 값만 달라도 네 칸을 다 쓴다 | `"{B>A:형/오빠/누나/언니}, 같이 가!"` (지금 대사에는 없음, 예비) |

| 카탈로그 | 줄마다 `g: ['A']` — 모습이 글에 영향을 주는 자리. 앱은 모습만 바뀐 동화에서 `g` 가 있는 줄만 다시 받는다 | 10줄은 `langs: ['en']` 만 |

## 5. 이용권(크레딧) 규칙 — 확정 (2026-11-06 사용자 결정)

### 5-1. 규칙

1. **4.99 전체 구매(unlockall)에 동화마다 첫 설정 1번씩 포함.** 네 편이면 네 번. 동화 하나를 설정해도 다른 동화의 첫 설정은 남는다.
2. 첫 설정을 쓴 동화를 **다시 바꾸려면 0.99 이용권 1장**. 이용권 1장은 **네 편을 한 번에(48시간 실행 하나 안에서) 모두 다시 바꿀 수 있다.** 동화별 1장이 아니다. 한 편만 바꿔도 1장을 쓴다.
3. 새 창작 동화가 추가되면 그 동화의 첫 설정이 새로 생긴다(= 규칙 1). 앞 기획의 '무료 보충(backfill)' 특별 규칙은 이 규칙에 흡수된다.
4. 주인공 모습 바꾸기는 그림이 앱 안에 있으므로 **횟수에 세지 않는다**. 단, 영어 모드에서 모습이 바뀌면 `g` 줄(동화당 1~8줄)을 다시 받아야 하는데, 이것은 그 동화의 첫 설정 실행 또는 이용권 실행 안에서만 만든다(실행 밖에서 모습만 바꾸면 영어 `g` 줄은 원래 녹음으로 재생되고 화면에 "영어 대사 몇 줄은 원래 모습으로 나와요" 한 줄).
5. 미리 듣기 하루 10회, 줄당 재시도 2회, 서버 하루 상한은 그대로.

### 5-3. 지금 규칙과 비교, 서버·KV 변경점

| 항목 | 지금(전체 1번) | 확정(동화별 첫 설정 + 이용권 1장 = 네 편) |

| 구매자당 무료 녹음 상한 | 한 벌 전체 1회(네 편 + 홈) | 동화마다 1회 = 합치면 같은 양. 한 편만 설정하는 구매자는 그만큼만 쓴다 → **평균 비용은 같거나 줄어든다** |
| 이용권 1장의 비용 | 한 벌 전체 1회(약 0.16달러 ko / 0.43달러 ko+en, 0.11 소모율 기준) | 같음(네 편 모두) |

| `POST /v1/name/line` | `names` | `names` + `look`(선택). 줄 카운터 `nl:<run>:<tale>:<id>:<lang>` 그대로 |

| 계정 합치기(`mergeName`) | used 합, covered 합집합 | `first` 합집합, `tickets` 합, 실행은 남는 계정 것 |
| **이전(마이그레이션)** | - | 서버가 옛 기록을 읽을 때 `used ≥ 1` 이면 `first = covered`(이미 받은 동화는 첫 설정을 쓴 것으로), `tickets` 그대로. 앱 `paperTheater.names` 도 동화별 `{ names, look, done, got }` 로 나누되, 옛 공통 이름은 네 편 모두에 복사 |
| KV 쓰기 수 | 한 벌 약 140번 | 동화별 실행이라 실행 만들기가 4번(8쓰기)으로 늘지만 줄 쓰기는 같음. 무시할 수준 |

핵심 진단 세 줄.
1. 심볼이 **뜻을 못 전한다**(이야기·아이·종이·톡톡 중 아무것도). 이야기 앱이라는 것은 글자를 읽어야 안다.
2. 아이콘 바탕이 **크림이라 화면에서 떠 있지 않고 묻힌다.** 아이콘은 앱 화면과 같은 색일 이유가 없다. 아이콘은 '봉투', 앱 화면은 '속지' 다.
3. 재료가 **앱과 다르다**(벡터 vs 오린 종이). 앱을 열면 종이인데 아이콘은 플라스틱이다.

## 2. 브랜드 핵심

- **한 문장 약속**: "톡 누르면 종이 무대가 열리고, 아이가 이야기 속으로 들어간다."
- **성격 세 단어**: 따뜻하다 · 손으로 만들었다 · 차분하다. (시끄럽지 않다. 밤에 틀어도 되는 앱이다.)
- **두 사람**:
  - 보호자가 산다(앱스토어 격자에서 2초 안에 "아, 이건 질 좋은 종이 동화책 앱이구나" 가 보여야 한다. 한 번 사는 4.99달러짜리 선물).
  - 아이가 누른다(홈 레일 48px 마크, 스플래시 끝 장면. 아이는 글자를 못 읽으니 **모양 하나**로 "내 동화 앱" 을 알아봐야 한다).
- **마크가 한눈에 말해야 하는 것(우선순위)**: ① 이야기(책·무대 중 하나) ② 종이로 만들었다(겹친 조각과 얕은 그림자) ③ 따뜻함(크림·구리·감빛 중 하나는 반드시) ④ 톡톡(움직임이나 고리로, 가능하면).
- **하지 않을 것**: 마스코트 얼굴(앱에 공통 마스코트가 없고, 아이 얼굴 금지 원칙과도 충돌), 그라데이션 바탕, 광택, 글자만 있는 아이콘(D 방향은 글자가 아니라 '오린 조각' 으로 다룬다).

## 3. 경쟁·맥락 — 앱스토어 격자에서 어떻게 보이나

내 기억에 있는 어린이 이야기·학습 앱 아이콘의 전형(검색 없이 적는다. 출시 전 실제 격자를 캡처해 다시 본다).

| 유형 | 예 | 특징 |
|---|---|---|
| **마스코트 얼굴** | 핑크퐁, 베이비버스(판다), 코코멜론, 토카보카, 사고미니, 링고키즈, 칸아카데미 키즈 | 밝은 단색 또는 그라데이션 바탕 + 캐릭터 얼굴 크게. 어린이 카테고리의 **7할** |
| **밝은 원색 + 글자·기호** | Epic!(청록 바탕 + 로고 글자), Vooks(파랑 + v), 카카오키즈(노랑) | 바탕이 채도 높은 파랑·청록·노랑·분홍. 흰 기호 |
| **책 모양** | Reading Eggs, Pickatale, 여러 전자책 앱 | 펼친 책 또는 책 더미. 파랑·주황이 많다 |
| **밤·달(잠자리 앱)** | Moshi(보라 그라데이션 + 달), Calm Kids | 어두운 보라·남색 + 달·별 |

격자에서 서는 방법.
1. **어두운 무광 단색 바탕**(남색·팥색·솔잎색)을 쓴다. 어린이 앱 격자는 밝은 파스텔과 그라데이션이 대부분이라 깊은 무광 한 색이 오히려 튄다. 크림은 배경화면에 녹는다.
2. **큰 실루엣 하나**. 아이콘 폭의 70% 이상을 차지하는 덩어리 하나. 작은 요소 여러 개는 60px 에서 죽는다.
3. **종이 질감이 180px 에서 보이게** — 조각 사이 얕은 그림자. 이것이 '손으로 만든 앱' 이라는 품질 신호이고, 벡터 마스코트들 사이에서 유일한 차별점이다.
4. **얼굴 없음**. 마스코트 사이에서 얼굴이 없는 것이 오히려 눈에 띄고, 보호자에게 '시끄럽지 않은 앱' 으로 읽힌다.
5. **따뜻한 빛 한 점**(크림 또는 앰버). 어두운 바탕에 따뜻한 빛은 '잠자리에 틀어 주는 앱' 을 말한다.

어린이 카테고리 제약(App Store 심사 1.3·2.3, 사람 인터페이스 지침 요약).
- 아이콘은 앱 내용과 맞아야 하고 오해를 주면 안 된다(실제 앱에 없는 캐릭터·사진 금지). 우리는 앱 안의 종이 스프라이트와 같은 재료를 쓰면 된다.
- 1024×1024 PNG, **알파 없음**, 꽉 찬 정사각형. 둥근 모서리는 iOS 가 자른다. 모서리에 중요한 것을 두지 않는다(안쪽 80% 안에).
- iOS 18부터 **다크·틴트 변형** 을 받는다. 다크 = 어두운 바탕 위 같은 마크(우리 아이콘은 이미 어두운 바탕이라 그대로 간다), 틴트 = 밝기 정보만 있는 단색 마스크(그림자 없이 실루엣만 남으므로 **실루엣만으로 읽히는 방향** 이 유리하다).
- 글자는 금지가 아니지만 지침이 말리고, 영어권에서 한글은 모양으로만 읽힌다. D 방향은 이것을 알고 가는 선택이다.
- 투명·광택·사진·UI 스크린샷을 아이콘에 넣지 않는다.

## 4. 방향 4개

공통 재료 규칙(네 방향 모두).
- 조각 3~5장 + 바탕 종이 1장. 1조각 1색, 무광, 종이결 보임. 조각 사이 2~4px 웜 다크 그림자(`#2E241C`)만. 바깥 그림자·테두리·흰 칼선 없음(아이콘은 스티커가 아니다).
- 광원 왼쪽 위 고정(DESIGN_SYSTEM 세트 A). 모든 그림자 오른쪽 아래 같은 방향.
- 아이콘 바탕은 **크림이 아니다**. 방향마다 팔레트의 어두운 색 하나.
- 16px 생존 규칙: 가장 가는 조각 폭 ≥ 아이콘 폭의 8%(1024 기준 82px), 조각 사이 틈 ≥ 6%. 이 수치를 프롬프트에 적는다.
- 앱 안 마크(48px)는 **같은 조각을 크림 위에 올린 것** 이다. 바탕색이 없어지므로 크림과 겹치는 조각(크림 책장 등)은 아래 조각의 색 테두리(rim)로 살린다.

### 방향 A — 「별이 뜬 책」 (logo_mark 를 키운다)

- **생각**: 지금 레일에 있는 펼친 책 + 구리 별을 **앱 전체의 마크로 승격** 한다. 책은 '이야기', 별은 '종이별 보상' 과 '밤' 을 한 번에 말한다. 가장 안전하고 빠르다.
- **심볼**: 정면에서 본 펼친 책. 크림 책장 두 장이 얕은 V, 그 아래 **구리 표지** 가 테두리로 보인다. 책 접힌 선 바로 위에 **구리 종이별 하나, 폭은 책의 1/3**(지금 1/5 → 16px 에서 살리기 위해 키운다). 조각 4장: 표지·왼쪽 장·오른쪽 장·별.
- **색**: 바탕 밤 남색 `#1F2A56`, 책장 크림 `#F6ECD8`, 표지·별 구리 `#C98A5B`. 지금 logo_mark 의 남색 표지는 남색 바탕에서 사라지므로 표지를 구리로 바꾼다(크림 위 마크에서도 구리 테두리가 책 윤곽을 잡아 준다).
- (a) **앱 아이콘 1024**: 남색 꽉 찬 바탕, 책 폭 72%, 책 세로 중심을 중앙에서 4% 아래(별 때문에 위가 무거워 보이지 않게).
- (b) **파비콘 32/16**: 남색 네모 + 크림 V 한 덩이 + 위에 구리 점. 16px 에서 별은 점으로 남아도 '책 위에 무엇' 으로 읽힌다. 32·16 은 1024 에서 줄이지 말고 **별을 20% 더 키운 전용 그림** 으로 따로 뽑는다.
- (c) **앱 안 마크 48**: 크림 바탕 위 같은 조각(바탕 없음). 지금 `logo_mark.webp` 자리 그대로.
- (d) **가로 조합**: 왼쪽 마크(높이 = 두 줄 글자 높이), 오른쪽 '톡톡 / 동화극장' 두 줄 또는 한 줄. 마크와 글자 사이 = 마크 폭의 1/3.
- (e) **스플래시**: 지금 7.4초 장면의 끝에서 책이 '쿵' 내려앉고 별이 0.3초 뒤 위에서 떨어져 앉는다(종이 무게, 튕김 없음). 그 아래 워드마크.
- **위험**: 책 아이콘은 많다(격자에서 '또 책 앱'). 별 + 어두운 남색으로 잠자리 앱 쪽에 가까워져 '놀이' 가 약하다. 틴트 모드에서 책 V 와 별만 남아도 읽히는 것은 장점.

### 방향 B — 「톡톡」 (두 번 두드린 종이 물결)

- **생각**: 앱 이름 그대로. 손가락으로 **톡, 톡** 두 번 두드리면 종이 물결(고리) 두 개가 퍼진다. 아이가 하는 유일한 조작 '누르기' 가 곧 브랜드다. 고리 두 개 = 톡톡.
- **심볼**: 가운데 **크림 동그라미 한 장**(손끝이 닿은 자리), 그 둘레에 **굵은 크림 고리 두 개**. 고리 굵기 = 아이콘 폭의 10%, 동그라미와 고리 사이 틈 7%. 동그라미가 맨 위, 안쪽 고리, 바깥 고리 순으로 아래로 깔려 각자 그림자를 갖는다. 조각 3장. 손가락 그림은 넣지 않는다(16px 에서 죽고, 3~4세는 고리만으로 충분하다).
- **색**: 바탕 **감빛 `#D9622F`**(앱의 '눌러 주세요' 색 그대로. 아이콘 자체가 '누르는 것' 이 된다), 동그라미·고리 크림 `#F6ECD8`. 앱 안 마크(크림 위)는 색을 뒤집어 감빛 고리·동그라미.
- (a) **앱 아이콘 1024**: 감빛 꽉 찬 바탕, 마크 지름 76%, 정중앙.
- (b) **파비콘 32/16**: 주황 네모 + 크림 과녁. 16px 에서 고리 굵기 1.6px → 안쪽 고리는 2px 로 살리고 바깥 고리는 뺀 **전용 2조각 그림** 을 쓴다.
- (c) **앱 안 마크 48**: 감빛 고리 두 개 + 동그라미(4.8px 굵기, 충분).
- (d) **가로 조합**: 마크를 '톡톡' 의 왼쪽에 두면 "(톡톡) 톡톡 동화극장" 으로 겹말이 된다. 마크를 **'톡톡' 글자의 받침 ㄱ 끝에 작은 고리** 로 붙이는 안과, 마크 단독 + '동화극장' 만 쓰는 안 두 가지를 시안으로 본다.
- (e) **스플래시**: 종이 위에 손가락 없이 **고리가 두 번 퍼진다**(톡, 톡 소리와 함께) → 두 번째 고리 안에서 무대 장면이 열린다 → 끝에 로고. 움직임이 뜻을 완성하는 방향이라 스플래시와 궁합이 가장 좋다.
- **위험**: 정지 그림만 보면 **과녁·라디오 단추·소리 인식 앱(Shazam)·무선 아이콘** 으로 읽힐 수 있다. '이야기' 를 전혀 말하지 않는다 → 보호자가 격자에서 그냥 지나칠 수 있다. 감빛 바탕은 어린이 앱 격자에 주황이 흔해서(Pickatale 등) 남색만큼 튀지 않는다.

### 방향 C — 「종이 극장」 (무대 구멍과 커튼)

- **생각**: '동화극장' 을 그대로. 팥색 커튼 벽에 **아치 모양 무대 구멍** 이 뚫려 있고, 구멍 안에서 **따뜻한 빛** 이 비친다(10-27 결정: 광원 그라데이션 허용). 구멍 안에 작은 종이 언덕과 별 하나. 앱의 '종이에 뚫린 구멍 속 무대'(CLAUDE §7-3 음각 무대) 원칙을 아이콘 한 장으로 압축한 것이다.
- **심볼**: 바탕 전체가 팥색 커튼 벽. 가운데 둥근 아치 구멍(폭 56%, 높이 66%). 구멍 안: 앰버 빛 종이(가운데가 크림으로 밝고 가장자리로 흐려짐 — 종이 뒤 빛이라 허용), 바닥에 솔잎색 언덕 한 장, 그 위 구리 별 하나. 구멍 위 테두리에 **짚빛 스캘럽 밸런스**(둥근 톱니 6~8개). 구멍 좌우 가장자리는 커튼을 막 걷은 듯 부드러운 물결. 조각 5장(커튼 벽·빛·언덕·별·밸런스).
- **색**: 바탕 팥색 `#A93B32`, 밸런스 짚빛 `#D9A94E`, 빛 앰버 `#F2B366`→크림 `#F6ECD8`, 언덕 솔잎 `#3F6B4F`, 별 구리 `#C98A5B`. 앱 안 마크는 **아치 모양 팥색 테 + 빛 + 밸런스** 3장(언덕·별 없음, 실루엣이 아치라 48px 에서 분명하다).
- (a) **앱 아이콘 1024**: 팥색 꽉 찬 바탕, 아치 정중앙. 아치 안이 아이콘에서 가장 밝은 곳이라 **격자에서 '불 켜진 작은 극장'** 으로 보인다.
- (b) **파비콘 32/16**: 팥색 네모 + 밝은 아치. 16px 에서 언덕·별·밸런스는 지우고 **아치 빛 한 덩이** 만 남긴 전용 그림. 가장 잘 버티는 방향이다(명암 대비가 크다).
- (c) **앱 안 마크 48**: 아치 테 + 빛 + 밸런스. 크림 위에서 팥색 아치가 또렷하다.
- (d) **가로 조합**: 아치 마크 왼쪽, 글자 오른쪽. 아치 높이 = 두 줄 글자 높이. 아치 안 빛은 글자와 같은 크림이라 흰 종이 위에서는 빛이 사라진다 → 흰 바탕용은 빛을 앰버 단색으로.
- (e) **스플래시**: 지금 장면 끝에 **커튼이 좌우로 걷히며** 아치가 열리고(0.5초), 아치 안에 무대 축소판(지금의 성·세 공주)이 들어간 뒤 아래 워드마크. 지금 scene.js 의 '무대를 작게 줄여 로고 아래 두는' 연출과 바로 이어진다.
- **위험**: 커튼 + 빨강 + 금색은 **영화·공연 예매 앱** 이나 설날 느낌으로 흐를 수 있다 → 팥색을 탁하게, 금색은 밸런스 한 줄만, 아치는 둥글게. 조각이 5장이라 네 방향 중 가장 복잡하다(생성 결과에서 조각 수를 센다). 틴트 모드에서는 아치 밝기 대비만 남는데 그것으로 충분하다.

### 방향 D — 「톡」 한 글자 (오린 종이 모노그램)

- **생각**: 캐릭터도 물건도 없이 **'톡' 한 음절을 가위로 오린 조각** 으로. ㅌ·ㅗ·ㄱ 세 조각이 겹쳐 쌓인다. 글자이지만 아이에게는 '모양', 보호자에게는 이름. 가장 과감하고 가장 한국적이다.
- **심볼**: '톡' 을 세로로 쌓은 세 조각: ㅌ(두 개의 열린 홈이 있는 두꺼운 E 모양), ㅗ(짧은 기둥 + 넓은 가로 바), ㄱ(넓은 바 + 오른쪽 짧은 갈고리). 획 굵기 = 아이콘 폭의 11%, 모서리 크게 둥글게. 조각 3장. 받침 ㄱ 은 몸통에 붙인다(sp_wordmark_v2 의 ㄱ 이 멀리 떨어진 문제를 피한다).
- **색**: 바탕 **솔잎 `#3F6B4F`**(어린이 앱 격자에 짙은 초록이 거의 없다), 글자 크림 `#F6ECD8`. 앱 안 마크(크림 위)는 글자 남색 `#222B45` — UI 글자색과 같아 머리줄 글자 로고와 한 몸이 된다.
- (a) **앱 아이콘 1024**: 솔잎 꽉 찬 바탕, 글자 폭 70%, 높이 78%.
- (b) **파비콘 32/16**: 32px 에서 ㅌ 가로획 3개가 각 3.5px, 틈 2.3px 로 읽힌다. **16px 에서는 ㅌ 의 세 획이 뭉친다**(획 1.7px). 16px 전용은 ㅌ 을 두 획(ㄷ 꼴)으로 단순화하거나 'ㅌ' 만 크게 넣은 변형을 따로 그린다. 네 방향 중 16px 이 가장 약하다.
- (c) **앱 안 마크 48**: 남색 '톡' 조각 3장. 48px 에서 획 5px, 문제없다.
- (d) **가로 조합**: 마크가 글자라 워드마크와 겹말이다. 조합에서는 **마크를 빼고 워드마크의 첫 '톡' 을 마크와 같은 조각 양식으로 그려** '톡'(크림 조각, 감빛 바탕 네모 안)+'톡 동화극장' 으로 잇는다. 즉 워드마크의 첫 글자가 마크다.
- (e) **스플래시**: ㅌ·ㅗ·ㄱ 세 조각이 위에서 차례로 떨어져 '톡' 이 되고(톡, 톡, 톡 소리 세 번 — 이름과 맞다), 옆에 '톡 동화극장' 이 이어 붙는다.
- **위험**: ① 한국에서 '톡' 은 **카카오톡** 연상이 세다(노란 말풍선과는 모양이 다르지만 이름이 같다). ② 영어권 격자에서 뜻 없는 모양이 된다. ③ 애플 지침이 아이콘 글자를 말린다. ④ 생성 모델이 한글을 정확히 쓰는 일이 불안정해 **sp_wordmark_v2.svg 의 ㅌ·ㅗ·ㄱ 윤곽을 코드로 조각내는 쪽** 이 더 확실하다(생성은 질감 참고용).

## 5. 글자 로고(워드마크)

- **표기**: 한글 '톡톡 동화극장'. 영어는 코드와 스플래시에 이미 'Tok Tok Tale Theater' 가 있고, 기획 가명은 'Paper Tale Theater' 다(§8-4 결정).
- **글자꼴 방향** — ⚠ 2026-10-28 사용자 확정으로 **대체됨: 글자 로고는 Pretendard 굵게(조합 A·B), 아래 '벡터 오린 글자(v2)' 권장은 쓰지 않는다**(맨 아래 확정 사항). 처음 권장안(오린 종이 글자, 벡터) 기록:
  - 한글 워드마크는 `assets/splash/draw_wordmark_v2.py` 의 **글꼴 없는 벡터 글자** 를 고쳐 쓴다. 이유: 소유권이 분명하고(글꼴 라이선스·생성물 저작권 문제 없음), 획 하나가 종이 띠 한 장이라 CLAUDE §7-5 '종이를 오려 얹은 글자' 와 재료가 같다. 고칠 것: 획 굵기를 '톡톡' 과 '동화극장' 모두 같은 단위(획 = 글자 높이의 14%)로, 모서리 반지름 = 획 굵기의 35%, ㅌ 가운데 획 두 글자 같게, 받침 ㄱ 을 몸통에 붙이기, ㅇ 은 정원에 가깝게. 조각마다 1px 웜 릴리프 그림자(SVG filter 또는 아래에 같은 모양 `#2E241C` 12% 1px 오프셋).

## 6. 생성 계획

작업표: `tools/app/gen/jobs_logo.json`(이 문서와 같이 만들었다). 실행은 기존 도구 그대로 `python3 tools/app/gen/run_simple.py logo <id ...>`(`jobs_<이름>.json` 규칙). 한 번에 2장씩, 한도에 걸리면 1시간 간격(CLAUDE §6-2).

| id | 무엇 | 바탕 | size | refs |
|---|---|---|---|---|
| `logo_A_icon` | 책+별 앱 아이콘, 꽉 찬 정사각 | 남색 | 1024² | logo_mark, star_one, tab_tales |
| `logo_A_mark` | 같은 조각, 마젠타 | 마젠타 | 512² | logo_mark, star_one |
| `logo_B_icon` | 고리 두 개 + 동그라미 | 감빛 | 1024² | star_one, ic_play |
| `logo_B_mark` | 감빛 고리, 마젠타 | 마젠타 | 512² | star_one |
| `logo_C_icon` | 커튼 벽 + 아치 빛 + 언덕 + 별 + 밸런스 | 팥색 | 1024² | sp_castle_v1, star_one, tab_tales |
| `logo_C_mark` | 아치 테 + 빛 + 밸런스, 마젠타 | 마젠타 | 512² | star_one |
| `logo_D_icon` | 크림 '톡' 조각 3장 | 솔잎 | 1024² | sp_wordmark_v2, star_one |
| `logo_D_mark` | 남색 '톡' 조각 3장, 마젠타 | 마젠타 | 512² | sp_wordmark_v2 |

프롬프트는 `tools/app/gen/jobs_ui.json` 의 `star_one` 틀(STYLE → CRITICAL STYLE RULE → ICON SET RULES → SUBJECT → FRAMING → LIGHTING → OVERALL FEELING → NO 목록)을 그대로 쓰고, 아이콘 작업은 FRAMING 만 "마젠타" 대신 **"꽉 찬 바탕 종이 한 장, 테두리·둥근 모서리·목업 없음, 중요한 조각은 안쪽 80% 안"** 으로 바꿨다. 16px 규칙(가장 가는 조각 ≥ 8%, 틈 ≥ 6%)을 ICON SET RULES 에 넣었다. 글자는 D 의 '톡' 한 음절만 허용하고 나머지는 NO text.

후처리.
1. 아이콘(`*_icon`): 크로마키 없음. 1024² 로 맞추고 알파 제거 → `assets/icons/app_icon_<방향>.png`. 바탕이 균일한 단색인지(생성물이 비네트를 넣었으면 다시) 네 모서리 픽셀을 비교한다.
2. 마크(`*_mark`): `tools/gpu_night/chromakey.py` → 트림 → 512² 캔버스 가운데 폭 80% → `assets/ui/logo_mark_<방향>.webp`.
3. 비교판: 네 방향을 **같은 캔버스** 에 180·60·32·16px 로 나란히 놓고, 양옆에 어린이 앱 아이콘 흉내(밝은 파랑·노랑·분홍 단색 네모 + 흰 원)를 두어 격자 상황을 흉내 낸 그림 한 장을 만든다. 라이트(흰 배경화면)·다크(검정 배경화면) 두 장.
4. 선택 뒤: 32·16 전용 그림(§4 각 (b))은 생성이 아니라 **선택된 1024 를 보고 벡터로 다시 그린다**(조각 수를 줄인 것이라 코드가 더 정확하다).
5. 파비콘·홈 화면 아이콘 교체는 `index.html` 12~14행 + 동화 31편 페이지 링크(커밋 ed8cfef4 에서 연결한 자리) + `?v=` 올리기.

| 6 | **종이로 보이나** | 180px 에서 조각 사이 그림자·종이결이 보이나. 벡터처럼 보이면 0 |
| 7 | **팔레트** | 바탕·조각이 전부 토큰 색이거나 §4 에 적은 추가 색인가. 유채색 그림자 없나 |
| 8 | **라이트·다크 배경화면** | 흰·검정 배경화면 위 둘 다에서 아이콘 테두리가 보이나(크림 바탕 실패의 재발 방지) |
| 9 | **틴트(단색) 모드** | 밝기만 남겨도 실루엣이 읽히나 |
| 10 | **글자 없음**(D 제외) | 생성물에 글자·기호가 섞이지 않았나 |
| 11 | **조각 수** | 프롬프트에 적은 수(3~5)와 같나. 많으면 16px 에서 죽는다 |
| 12 | **앱 안 마크와 같은 물건인가** | 아이콘과 48px 마크를 나란히 놓고 같은 조각으로 보이나 |
| 13 | **움직임이 있나** | 스플래시에서 뜻을 더하는 움직임(열림·퍼짐·떨어짐)이 자연스러운가 |
| 14 | **얼굴·저작권·실제 아이** | 없음을 확인(0이면 탈락) |
| 15 | **1년 뒤에도 괜찮나** | 유행 요소(그라데이션·3D 광택)가 없나 |

합계가 아니라 **1·3·4·8 이 모두 2점인 후보** 중에서 고른다. 1·8 이 1점 이하면 탈락.

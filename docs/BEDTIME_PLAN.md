# 잠자리 이어 듣기 기획 — 랜덤 연속 재생 + 재생목록

> 2026-10-27 사용자 지시: "잠자리는 랜덤 연속 재생 + 재생목록하는 기능 추가". `docs/APP_SCREENS_PLAN.md` §7 판단 #7(잠자리 이어 읽기는 출시에 없음)을 뒤집는다.
> 이 문서는 기획서다. 앱 코드는 아직 고치지 않았다. 근거: `docs/READ_MODE.md` §10-4, `engine/tale.js` readPlay, `audio.js`, `home.js` S2, `tales/catalog.js`, `ios/App/App/Info.plist`, 헤드리스 크롬 시험(§3).

## 0. 한 줄
잠자리 탭에 **「아무 이야기나 이어 듣기」(랜덤)**와 **「우리 재생목록」(보호자가 고른 순서)**을 두고, 둘 다 **한 페이지짜리 잠자리 듣기 플레이어(`bedtime.html`)**에서 오디오 한 흐름으로 이어 재생한다. 화면이 꺼지거나 기기가 잠겨도 다음 동화로 넘어가야 하므로 동화 페이지를 차례로 이동하는 방식은 쓰지 않는다.

## 1. 권장 방식과 이유

### 1-1. 세 방식 비교

| | (가) 동화 페이지를 차례로 이동 | **(나) 잠자리 전용 듣기 플레이어 (권장)** | (다) 혼합: 켜짐=가, 꺼짐=나 |
|---|---|---|---|
| 화면 꺼짐 중 다음 동화 | 페이지 이동 = 문서를 버림. 무음 유지 `<audio>`(keepAlive)·내레이션 `<audio>`·Media Session 이 그 순간 모두 끊기고, 새 문서가 js·대본·녹음을 다시 받아 재생을 시작해야 한다. iOS 는 배경에서 오디오가 멈춘 앱을 곧 정지시키므로(시간은 문서화돼 있지 않음) 이 틈에 끊길 위험이 가장 크다 | 문서 하나. 무음 유지 루프와 내레이션 요소가 처음 누름에서 끝까지 살아 있고, 동화 사이도 같은 `<audio>` 의 `ended → 다음 src` 사슬이다(한 편 안에서 이미 쓰는 방식, READ_MODE §10-4) | 꺼짐을 감지해 (나)로 바꾸는 순간이 곧 (가)의 위험 지점이다. 두 플레이어를 다 만들고 전환 상태까지 다뤄야 한다 |
| 화면 켜짐 중 그림 | 놀이판 장면 연출 그대로(가장 좋다) | 표지 키아트 + 장면 카드 글자 + 자막. 장면 연출은 없다(동화마다 코드 안의 READ_ACTS 라 밖에서 재현할 수 없다) | (가)와 같다 |
| 작업량 | 끝 화면에서 다음 동화로 가는 길 + 각 동화 페이지의 자동 시작 + 큐 상태를 `sessionStorage` 로 넘김. 31편 공통 엔진이라 코드 자체는 적다 | 새 페이지 1장(html+js), 플레이어 루프(대본·녹음 맵 읽기·줄 순서 재생), S2 단추·설정·재생목록 편집 | (가)+(나) 둘 다 |
| 아이 경험 | 켜져 있을 때 가장 풍부. 꺼짐 중 끊기면 잠들던 아이가 깬다 | 잠자리는 소리가 핵심이다. 한 편만 그림과 함께 듣고 싶을 때는 **지금 동화 페이지의 읽어 주기**를 그대로 쓴다(두 입구 유지, §1-3) | 켜짐에서 좋으나 전환 때 그림·소리가 한 번 끊긴다 |

### 1-2. 결론
- **(나)로 확정 제안.** 잠자리의 목적(화면을 끄고 잠들 때까지 끊기지 않기, 메모 `feedback-read-mode-sleep`)에 가장 맞고, 위험 지점이 '처음 누름' 한 곳뿐이며, 한 편 안에서 이미 검증된 `<audio>` 사슬을 동화 사이로 늘리는 것뿐이다.
- 버린 안
  - (가): 헤드리스 크롬에서는 가려진 탭에서도 페이지 이동 뒤 자동 재생이 됐지만(§3), iOS 잠금은 '탭 가림'이 아니라 프로세스 정지·오디오 세션 정책이라 같다고 볼 수 없다. 이동 순간 오디오 세션이 비는 구조적 틈을 없앨 수 없다.
  - (다): 두 플레이어와 전환 상태를 모두 안고 가면서 (가)의 틈은 그대로 남는다.

### 1-3. 입구는 둘, 플레이어는 하나
- 잠자리 탭 타일을 톡 → 지금처럼 그 동화 페이지의 읽어 주기(`?read=1`, 그림 연출 있음, 한 편). 바꾸지 않는다.
- 「이어 듣기」·「재생목록」 → `bedtime.html` 플레이어(소리 중심, 여러 편). 새로 만든다.
- 한 편 읽어 주기도 화면이 꺼지면 끝까지 읽는다(READ_MODE §10-4). 이어 듣기는 '다음 편으로' 만 플레이어가 맡는다.

- 읽기 대본이 참조하는 ElevenLabs 녹음 용량: **한국어 141.6MB, 영어 4.8MB**(`audio/el` 전체는 397MB).

### 2-2. 선결 과제 — 앱 번들에 ElevenLabs 녹음이 없다 (코드 확인, 실기기 미확인)
- `tools/app/build_www.sh` 는 `audio/tc` 만 복사한다(`rsync audio/tc www/audio/`). `ios/App/App/public/audio/` 에는 `tc` 뿐이다.
- 그런데 동화 페이지는 기본으로 `narration_el.js`·`read_narration_el.js` 를 읽고(`localStorage voice !== 'tc'`), 이 맵은 `audio/el/…` 를 가리킨다. 앱 안에서 `capacitor://localhost/audio/el/…` 는 404 다.
- 예상 결과: 놀이판은 녹음 실패 → 브라우저 TTS 로 떨어지고, 읽어 주기는 `recordedOnly` 라 **그 줄을 건너뛴다(소리 없음)**. 잠자리 플레이어도 같은 녹음을 쓰므로, 이것을 먼저 풀어야 한다.
- 권장: `build_www.sh` 에 `audio/el` 을 넣는다(전체 397MB. 읽기용만 넣으려면 31편 `read_narration_el*.js` 가 참조하는 파일만 골라 146MB). 앱 크기는 지금 848MB(`ios/App/App/public`) → 약 1.0~1.25GB. 셀룰러 다운로드 한도(200MB)는 이미 넘어 있으므로 판단은 '용량을 얼마나 더 허용하나'뿐이다. → §9 판단 1.
- 잠금 중 서버에서 받아 오는 방식은 쓰지 않는다(오프라인 불가, 배경 네트워크 불확실).

### 2-3. 엔진에서 가져올 것 (`engine/tale.js` readPlay, `audio.js`)
- 처음 누름 안에서 `AudioFX.mediaNarration(true)`(내레이션 `<audio>` + 합창용 요소 7개를 무음으로 한 번 재생해 iOS 허락을 받음) + `AudioFX.unlock()`(무음 반복 `<audio>` keepAlive, `navigator.audioSession.type='playback'`).
- 줄 재생: `Narrator.speak(text, { recordedOnly: true, simultaneous })` 그대로 쓸 수 있다(말풍선 요소 `#bubble`·`#bubbleText` 만 플레이어 페이지에 두면 된다). 시간 제한은 readPlay 의 `guard`(녹음 길이 + 3초, 길이 모르면 8초 + 글자당 0.25초)를 옮긴다.
- `document.hidden` 이면 줄 사이 쉼(700/1500ms)을 건너뛰고 `ended` 로 바로 잇는다. 가린 탭의 타이머는 1초 단위로 늘어지지만(§3 chain-hidden-gap: 2.5초 쉼이 2.52초) 동작은 한다.
- Media Session: 제목·표지·`pause`/`play` 는 지금 코드와 같고, 플레이어는 **`nexttrack`(건너뛰기)** 를 더한다.
- `AudioFX.narHold(on)` = 잠금 화면 일시정지. `visibilitychange` 에서 읽는 중이면 keepAlive 를 놓지 않는다(`mediaNar` 참일 때).

## 3. 헤드리스 크롬 시험 (2026-10-27, Chrome 156.0.8078.48, macOS)

시험 파일: `/private/tmp/claude-501/-Users-house-of-4k2b-projects-2026-patjuk-game/b4842b92-f585-4bc1-9ed2-20ae37209aff/scratchpad/bedtime/`(chain.html, nav1.html, nav2.html, cdp.mjs, run.sh, 팥죽 녹음 6조각 3.6~6.5초). CDP 로 실제 마우스 누름을 넣고, 다른 탭을 앞으로 가져와 시험 탭을 가렸다(`document.visibilityState === 'hidden'` 확인).

| 시나리오 | 결과 |
|---|---|
| **chain-hidden** — (나) 모사: `<audio>` 하나로 6조각 `ended → 다음 src`, 첫 조각 1.5초 뒤 탭 가림 | 가린 채 **완주** 29.2초(조각 길이 합 29.0초). 조각 사이 틈 20~25ms. |

| **nav-visible** — (가) 모사: 누름 → 1조각 → `location.href` 로 다음 문서 → 누름 없이 `play()` → 또 이동 | 두 번 모두 재생 OK. 새 문서의 `navigator.userActivation.hasBeenActive === true`(크롬은 같은 출처 이동에 사용자 활성화를 넘긴다). 문서 사이 틈 6~9ms. |
| **nav-hidden** — 위와 같되 가린 채 | **가린 채 두 번 이동 모두 재생 OK.** |
| **nav-auto** — 누름 없이 첫 문서에서 `play()` | `NotAllowedError`(자동 재생 정책). 누름은 반드시 필요. |

해석
- 크롬(데스크톱·안드로이드 크롬)에서는 (가)·(나) 모두 가려진 상태에서 이어진다. 차이는 iOS 에서 난다.
- iOS·WKWebView 와 다른 점(실기기 확인 필요): ① iOS 잠금은 탭 가림이 아니라 앱 프로세스 정지다. 배경 오디오 모드가 있어도 **오디오가 멈춘 순간부터** 앱이 정지될 수 있어, (가)의 문서 전환 틈이 위험하다. ② 사파리(웹)는 새 문서에 사용자 활성화를 넘기지 않아 (가)의 자동 재생이 막힐 수 있다. Capacitor 의 WKWebView 는 `mediaTypesRequiringUserActionForPlayback = []` 로 만들어져(코드 확인: `node_modules/@capacitor/ios/Capacitor/Capacitor/CAPBridgeViewController.swift:125`) 앱 안에서는 누름 없는 `play()` 가 허용된다. ③ Web Audio(효과음)는 잠금 중 나오지 않는다(READ_MODE §10-4). 플레이어는 효과음을 쓰지 않는다.

## 5. 규칙

### 5-1. 랜덤 후보
- 잠자리 탭 목록(`home.js nightList` = `t.read && inScope(t) && isOpen(t)`, 잠긴 동화도 마개로 보임)에서 **잠긴 것을 뺀 것**: `t.read && inScope(t) && isOpen(t) && Entitlements.canPlay(t.id)`. '만드는 중'·잠긴 동화는 뽑지 않는다. 웹 공개판은 잠금이 없으니 31편 전부.
- 같은 회차 안에서 같은 동화를 두 번 뽑지 않는다. 후보가 편 수보다 적으면 후보 수만큼만 듣고 끝낸다.
- **최근 들은 8편(`paperTheater.recentRead`)은 뒤로 미룬다**: 후보에서 최근 8편을 뺀 것에서 먼저 뽑고, 모자라면 최근 것에서 뽑는다. 같은 동화가 매일 나오는 것을 피하되 금지는 아니다.
- 플레이어가 재생한 편은 `recentRead` 에 넣는다(지금 `startRun` 이 하는 것과 같은 키·8편).

### 5-2. 몇 편까지 — '편 수'만 두고 '분'은 두지 않는다
- 보호자 설정 **"○편 듣고 끄기": 1·2·3·5편, 기본 2편**(약 10~15분). 5편은 상한이다(잠든 뒤 한 시간 넘게 틀어 두지 않게).
- '○분 뒤 끄기'는 두지 않는다. 동화 중간에 뚝 끊기면 잠들던 아이가 깨고, 어차피 한 편이 5~13분이라 편 수로 충분하다. → §9 판단 2.
- 재생목록 모드는 목록 길이(최대 5)가 곧 편 수다.
- **놀이 시간(S9·S13)과의 관계**: 플레이어 회차는 놀이 시간에 **세지 않고**(`PT.run` 을 부르지 않음) 쉬는 화면도 끼어들지 않는다. APP_SCREENS 판단 #6(잠자리 읽기 중엔 끼어들지 않음)과 같은 뜻이며, 보호자 글 "놀이 시간은 화면을 보는 시간"과도 맞는다. 놀이 시간이 이미 다 됐어도 플레이어는 켤 수 있다(보호자가 켜는 것이고 화면은 곧 어두워진다).

### 5-3. 동화 사이
- 끝 → **쉼 3초(무음)** → **다음 동화 제목 읽기**(홈 제목 녹음 `home_narration_el.js`, 영어 모드면 영어 제목 녹음, 없으면 건너뜀) → 1초 → 첫 줄. 새 녹음은 없다.
- 종이 넘김 효과음은 쓰지 않는다(Web Audio 는 잠금 중 안 나오고, `<audio>` 로 틀면 세션을 하나 더 쓴다. 조용한 쪽이 잠자리에 맞다).
- 쉼 동안 세션은 keepAlive 무음 루프가 붙잡는다(지금 읽어 주기와 같음). 쉼이 3초라 "무음으로 배경에 남는" 모양이 되지 않는다(§6-4).
- 한 편 안의 줄 사이 쉼은 readPlay 와 같다(700ms, 장면 끝 1500ms, 안 보이면 건너뜀).

### 5-4. 멈춤·건너뛰기·중단
- 멈춤: `AudioFX.narHold(true)` + Media Session `paused`. 다시 누르면 그 줄 이어서.
- 건너뛰기: 지금 줄을 멈추고(`Narrator.stop`) 바로 '동화 사이' 순서로. 남은 편 수에서 1을 쓴다(건너뛴 편도 센다).
- [집]: 세션을 끄고 홈 잠자리 탭으로. 이어 듣기 위치를 기억하지 않는다(다음에 켜면 새 회차).
- 앱이 죽거나 iOS 가 정지시킨 경우: 다시 열면 홈이다. 복구 없음(단순하게).
- 전화·시리 등 끼어듦(AVAudioSession interruption): WebKit 이 `<audio>` 를 멈춘다. 끼어듦이 끝나면 `narEl` 의 `pause` 이벤트와 `ended` 없이 멈춘 상태를 시간 제한(녹음 길이 + 3초)이 잡아 다음 줄로 넘어간다. 실기기 확인(§8).

### 5-5. 같은 동화 반복
- 한 회차 안에서 반복 금지(5-1). 재생목록은 같은 동화를 두 번 넣을 수 없다(편집 시트에서 체크 토글).

### 5-6. 영어 모드
- 후보는 `readEn: true` 인 동화만(지금 팥죽 1편). 영어 모드에서 한국어 녹음으로 이어 듣지 않는다(언어가 섞이면 잠자리에 어색). 후보가 1편이면 단추 글자를 "영어 이야기 1편 듣기"로 바꾸고 그 편만 듣고 끝낸다. 0편이면 단추 비활성 + 안내(4-1 4번). → §9 판단 8.
- 재생목록에 영어 녹음 없는 동화가 들어 있으면 영어 모드에서는 그 편을 건너뛰고 S2 카드에 '한국어만' 표시를 그 표지에 붙인다(지금 타일 표시와 같은 글자).

### 5-7. 저장
- 로컬 `localStorage` 키 `paperTheater.bedtime` = `{ count: 2, playlist: ["rabbit","turnip"] }`. 웹·앱 공통.
- 동기화 state(SYNC_API)에는 **넣지 않는다**. 재생목록은 '순서'가 있는 값이라 기존 합치기 원칙(합집합·최솟값, 순서 무관)에 맞지 않고, 기기마다 잠자리 취향이 달라도 된다. 넣어야 한다면 제안만: `bedtime: { playlist: [...], count, updatedAt }` 를 더하고 `updatedAt` 이 큰 쪽이 이기는 규칙을 SYNC_API 에 새로 적는다(첫 '최신 우선' 필드가 되므로 서버 코드도 바뀐다). → §9 판단 12.

### 5-8. 보상·기록
- 종이별·스티커는 주지 않는다(사용자 결정, SYNC_API `earned`·`stickers` 는 놀이 완주만). `Entitlements.finishPlay` 를 부르지 않는다.
- `recentRead` 만 기록한다(5-1).

### 5-9. 끝낼 때 세션 정리 (심사와 배터리)
- 마지막 편 끝 → 쉼 3초 → `AudioFX.narHold(true)` 가 아니라 **끄기**: 내레이션 `<audio>` `src` 비움, keepAlive 루프 `pause()`, Media Session `playbackState='none'`·핸들러 제거, 네이티브 `BedtimeAudio.end()`(§6-2)로 세션 비활성. 그 뒤로는 앱이 배경에서 할 일이 없다.

## 7. 구현 단계 (작게, 각 단계 끝에 확인)

0. **선결**: `build_www.sh` 에 `audio/el` 포함(§2-2) → iOS 시뮬레이터·실기기에서 읽어 주기 한 편에 소리가 나는지. 그 다음 §6 #1·#2 만 넣고 **지금 엔진의 한 편 읽어 주기**가 잠금 중 끝까지 가는지 실기기 확인(READ_MODE §10-4 미확인 항목). 여기서 안 되면 플레이어를 만들어도 소용없다.
1. `bedtime.html` + `bedtime.js` 뼈대: `audio.js`·`tales/catalog.js`·`entitlements.js`·`home_narration_el.js` 만 로드. 주소 `?mode=random|list`, 시작 화면 큰 단추, 누름 안에서 `mediaNarration(true)`·`unlock()`·`BedtimeAudio.begin()`. 큐 만들기(5-1·5-2). 플레이어 루프: 동화마다 대본 fetch → 녹음 맵 `new Function` 으로 `NARRATION_CLIPS(_EN)` 에 합침 → 장면·줄 순서대로 `Narrator.speak(text, { recordedOnly: true, simultaneous })` + 시간 제한 guard + 쉼(안 보이면 건너뜀) → 클립 없는 줄 건너뜀. 화면: 표지·제목·카드·자막. 콘솔 `[bedtime] <id> N/M` 과 `window.__BED`(queue, idx, said, skipped, timeouts, done).
2. 동화 사이(5-3), 멈춤·건너뛰기·[집](5-4), Media Session(play/pause/nexttrack), 60초 덮개, 끝 화면, 세션 끄기(5-9).

## 11. 확정 사항 (이 문서 기준, 사용자 확인 전)
- 방식 (나): `bedtime.html` 한 페이지에서 오디오 한 흐름으로 이어 듣기. 동화 페이지 이동 없음.
- 입구: S2 카드 두 장(랜덤·재생목록). 타일 톡의 한 편 읽어 주기는 그대로.
- 편 수 1·2·3·5(기본 2), 분 단위 없음. 같은 회차 반복 없음, 최근 8편은 뒤로. 동화 사이 무음 3초 + 제목 읽기.
- 종이별·스티커 없음. 놀이 시간에 세지 않고 쉬는 화면 없음. 재생목록은 로컬 1개(최대 5편), 동기화 안 함.
- 끝나면 세션을 끄고 어두운 끝 화면. 화면 켜짐을 붙잡지 않는다.
- 네이티브: `UIBackgroundModes audio`, AVAudioSession `.playback`(시작 때 켜고 끝나면 끔), 작은 플러그인 `BedtimeAudio`. 잠금 화면 표시는 웹 Media Session 먼저.
- 선결: 앱 번들에 `audio/el` 포함, 실기기에서 한 편 읽어 주기 잠금 완주 확인.
